# P1: Embedding Gateway

**ата:** 2026-05-05
**Статус:** ✅ Merged (PR #26)

## то сделано

Создан единый шлюз для получения эмбеддингов поисковых запросов —
метод `_encode_query()` с декоратором `@lru_cache(maxsize=128)`.

се поисковые запросы (`search_all`, будущие BM25-методы) обязаны
проходить через этот шлюз. рямые вызовы `self.model.encode()` запрещены.

## рхитектурное значение

- **динственная точка входа** для получения эмбеддингов
- **эширование** — повторные запросы не нагружают модель
- **отовность к BM25** — второй ранкер будет использовать тот же шлюз
- **прощение тестирования** — достаточно замокать один метод

## обавленные тесты

- `test_search_all_uses_gateway` — проверяет, что `search_all` вызывает
  `_encode_query`, а не `model.encode` напрямую
- `test_repeated_query_uses_cache` — проверяет кэширование при повторных запросах

## зменения в коде

- етод `_encode_query` помечен как EMBEDDING GATEWAY (P1)
- обавлена аннотация возвращаемого типа `-> List[float]`
- омментарий-маркер: "All search queries MUST use this method.
  Direct calls to self.model.encode() are forbidden."
